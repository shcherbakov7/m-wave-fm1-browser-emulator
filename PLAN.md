# M-VAVE FM-1 — браузерный эмулятор: промпт и план

## 1. Промпт (задание самому себе)

> Построй в репозитории `m-wave-fm1-browser-emulator` браузерный эмулятор синтезатора
> M-VAVE FM-1, который запускает **немодифицированные бинарные прошивки** (стоковые
> `FM-1.fwsc` V13–V15 и сторонние: Felucca, SLOOP, Groove OS, Baud Girl и т.д.).
> Пользователь перетаскивает файл прошивки в страницу → эмулятор распаковывает
> JieLi UFW-контейнер, раскладывает образ во виртуальный SPI-flash (XIP @ 0x02000000),
> исполняет код на эмулированном ядре **pi32v2** (JieLi AC791N / WL82), эмулирует
> периферию (дисплей 240×240, 27 клавиш, кнопки с LED, энкодеры/ручки, аудио-DAC,
> USB-MIDI, таймеры, прерывания) и выводит картинку на `<canvas>`, звук — через
> AudioWorklet, управление — мышью/клавиатурой/Web MIDI.
> Ядро эмулятора — C/C++ или Rust → WebAssembly, работает в Web Worker.
> Нет данных — сначала исследуй (прошивка, SDK JieLi AC79, Ghidra-модуль pi32v2,
> RE-репозитории), затем фиксируй находки в `docs/`. Каждый шаг покрывай тестами
> (юнит-тесты инструкций, сравнение трасс), коммить маленькими шагами.
> Стоковые прошивки и SDK в репозиторий не кладём (лицензии) — только загрузка пользователем.

## 2. Что известно (исследование)

| Компонент | Факт | Источник |
|---|---|---|
| SoC | JieLi AC791N (серия WL82), 2 ядра | aroum/fm1-custom-fw, ip2k/lunar-modulator |
| ISA | **pi32v2** — проприетарная JieLi, публичной документации нет; есть SLEIGH-модуль для Ghidra | aroum/fm1-custom-fw, AL-255/FM-1-RE |
| Память | SPI-flash 4/8 МБ, XIP через кэш @ 0x02000000; UBOOT в 0x0–0x4000, приложение с 0x4000/0x10000 | aroum/fm1-custom-fw |
| Формат прошивки | UFW (`@JMUA`, `JLUFW`, тег `AC791N`), без шифрования/подписи, 8-битные суммы | aroum/fm1-custom-fw |
| Дисплей | цветной 240×240 (контроллер — уточнить, вероятно ST7789 по SPI) | lunar-modulator |
| Управление | 27 клавиш (16 белых), ~14 кнопок с подсветкой, 4 ручки + MASTER + ещё 2 энкодера | lunar-modulator |
| I/O | USB-C: USB-MIDI (+ USB-аудио в некоторых прошивках), TRS MIDI IN | aroum/fm1-custom-fw |
| Существующие «эмуляторы» | только WASM-сборки исходников конкретных прошивок (не бинарей) | lunar-modulator, FiMba-1, SLOOP |

**Главный вывод:** «любая прошивка» = эмуляция **на уровне инструкций** pi32v2 + регистров
периферии AC791N. Готовых эмуляторов этого ядра нет — это и есть основная работа и
основной риск.

## 3. Архитектура

```
 Браузер (main thread)                       Web Worker                    AudioWorklet
┌─────────────────────────┐   postMessage   ┌──────────────────────────┐  SharedArrayBuffer ┌──────────┐
│ UI: корпус FM-1 (SVG)   │◄──────────────► │ emu-core.wasm            │ ─── кольц. буфер ─►│ вывод    │
│ canvas 240×240          │  framebuffer    │  ├ CPU pi32v2 (×2 ядра)  │                    │ 48 кГц   │
│ клавиши/кнопки/ручки    │  input events   │  ├ шина/MMIO, flash XIP  │                    └──────────┘
│ Web MIDI in/out         │                 │  ├ IRQ-контроллер, таймеры│
│ загрузка .fwsc/.ufw/.bin│                 │  ├ GPIO/матрица клавиш   │
│ отладчик (регистры,     │                 │  ├ SPI+DMA → LCD-контроллер│
│  дизассемблер, трасса)  │                 │  ├ ADC/энкодеры          │
└─────────────────────────┘                 │  ├ Audio DAC + DMA       │
                                            │  └ USB-MIDI (HLE)        │
                                            └──────────────────────────┘
```

- Ядро: **Rust → wasm32** (wasm-bindgen) — безопасность, хорошие тесты, без Emscripten.
- Фронтенд: TypeScript + Vite, без тяжёлых фреймворков.
- Хостинг: GitHub Pages (нужен COOP/COEP для SharedArrayBuffer → service worker-шим).

## 4. План по этапам

### Этап 0 — Исследование и инструменты (обязательно до кода)
1. Скачать стоковую прошивку (официальный апдейтер) и 1–2 open-source прошивки с исходниками
   (Felucca, fm1-nes) — исходники + бинарь = эталон для сверки.
2. Написать распаковщик UFW (`tools/ufw`), вытащить образ приложения, проверить суммы.
3. Взять SLEIGH-спецификацию pi32v2 (Ghidra) как спецификацию ISA; собрать таблицу кодировок
   в `docs/isa-pi32v2.md`. Дизассемблировать стоковую прошивку, найти точку входа, векторы
   прерываний, адреса MMIO.
4. Из JieLi AC79 SDK (Apache-2.0) извлечь карту регистров периферии AC791N
   (`docs/memory-map.md`): тактирование, GPIO, таймеры, SPI, DMA, IRQ, AUDIO/DAC, USB, ADC.
5. Определить по коду прошивки контроллер дисплея и способ опроса клавиш/энкодеров.

**Результат:** документы ISA/memory-map, распаковщик, понятная карта «что нужно эмулировать».

### Этап 1 — CPU pi32v2
1. Декодер + интерпретатор всех инструкций (ALU, загрузки/сохранения, ветвления, умножение/
   MAC, системные регистры, исключения/прерывания, режимы привилегий).
2. Дизассемблер (нужен для отладки и тестов).
3. Тесты: на каждую инструкцию; прогон кусков стоковой прошивки и сравнение с ожиданиями
   из Ghidra p-code (эмуляция p-code как «оракул»).
4. Второе ядро — как отдельный экземпляр CPU с общей шиной (пошаговая синхронизация).

### Этап 2 — Система и загрузка
1. Шина памяти: flash (XIP, кэш как прозрачный), SRAM, ROM-заглушка, MMIO-диспетчер.
2. HLE загрузки: вместо mask ROM/UBOOT сразу настраиваем состояние и прыгаем в приложение
   (опционально — запуск UBOOT, если удастся).
3. Тактирование, таймеры, контроллер прерываний, watchdog (заглушка).
4. Логгер неизвестных MMIO-обращений — главный инструмент «доведения» периферии.

**Веха:** стоковая прошивка доходит до главного цикла без падений.

### Этап 3 — Периферия
1. SPI + DMA → эмуляция LCD-контроллера (команды CASET/RASET/RAMWR и т.п.) → framebuffer.
2. GPIO/матрица клавиш, кнопки, LED.
3. Энкодеры/ручки (квадратурные входы или ADC — по результатам этапа 0).
4. Аудио: DAC/I2S + DMA → ресемплинг → кольцевой буфер → AudioWorklet.
5. USB-MIDI на уровне HLE (пакеты в/из USB-endpoint ↔ Web MIDI / экранная клавиатура).
6. Энергонезависимое хранилище (VM-область flash) → IndexedDB, чтобы пресеты сохранялись.

**Веха:** стоковая прошивка показывает экран, реагирует на клавиши и звучит.

### Этап 4 — Фронтенд
1. Корпус FM-1 в SVG с теми же элементами: экран, 27 клавиш, кнопки с LED, 7 ручек.
2. Ввод: мышь/тач, раскладка компьютерной клавиатуры, колесо/drag для ручек, Web MIDI.
3. Загрузка прошивки drag-and-drop, список последних (IndexedDB), сброс/пауза/скорость.
4. Панель отладчика: регистры, дизассемблер, брейкпоинты, MMIO-лог, просмотр памяти.

### Этап 5 — Совместимость и производительность
1. Прогон набора прошивок (стоковые V13–V15, Felucca, SLOOP, Groove OS, fm1-nes…),
   таблица совместимости в README.
2. Профилирование: цель — реальное время на среднем ноутбуке. Если интерпретатора мало —
   кэш декодированных блоков, затем (опционально) JIT в WASM-модули.
3. CI (GitHub Actions): тесты ядра, сборка, деплой на GitHub Pages.

## 5. Риски и как с ними работать

| Риск | Вероятность | Митигирование |
|---|---|---|
| Неполная/неточная спецификация pi32v2 | высокая | Ghidra SLEIGH + p-code как оракул; сверка на прошивках с исходниками |
| Нет документации на периферию | высокая | SDK AC79 (заголовки регистров), MMIO-лог, итеративная доводка |
| Прошивки используют DSP/спец. инструкции для FM-синтеза | средняя | эти инструкции — в приоритете, отдельные тесты |
| Производительность (2 ядра, ~300 МГц, аудио в реальном времени) | средняя | блочный кэш, затем JIT; режим «медленнее реального времени» как fallback |
| Нет физического устройства для сверки | высокая | эталон — open-source прошивки и их собственные веб-симуляторы |
| Лицензии | — | стоковые прошивки и SDK не храним в репо, пользователь загружает сам |

## 6. Порядок работы в этой сессии

Реалистично за одну сессию: **этап 0 полностью + каркас проекта + начало этапа 1**
(UFW-распаковщик, декодер/дизассемблер pi32v2, интерпретатор базовых инструкций, каркас
UI с загрузкой прошивки и экраном). Полностью рабочий эмулятор «любой прошивки» — это
многоэтапная работа, дальше идём итерациями по вехам выше.
